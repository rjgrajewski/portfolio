## 2026-08-30 — Desktop two-zone layout

- 2026-08-30 — **Desktop (≥1024px) restructured from a single scrolling column into a two-zone layout: content zone left (flexible width), agent zone right (fixed 380px), both visible at once, page-level scroll disabled** — implemented as a pure CSS Grid switch (`.app-layout` in `styles/index.css`), not a second DOM tree or a JS-driven layout fork. Below 1024px the grid is inert (`display: block`) and the page is the exact Phase 1 single column; at 1024px the same markup becomes a 3-row grid (header / compact intro / content+agent), with the last row's two cells independently `overflow-y: auto`. Reasoning for each specific call:
  - **Why a CSS-only switch instead of two conditionally-rendered layouts:** the two candidate layouts share stateful children (`PortfolioSections` reads the shared `activeSectionStore`). Mounting it twice — once per layout, toggled by Tailwind's `hidden`/`lg:hidden` — would put two elements with the same `id`/`aria-controls` values in the DOM simultaneously, which is invalid HTML and breaks the `aria-controls` reference. A single mount, repositioned by CSS, has no such collision and needed no new state or a `useMediaQuery` hook.
  - **Why content is left and the agent is right:** two competing conventions exist — "canvas" tools like ChatGPT/Claude put chat left and generated content right, while site-embedded assistants (Intercom, Drift, most AI website widgets) dock right. This product is closer to the second: docs/ARCHITECTURE.md § Product shape is explicit that the manual click-through is "a complete, real alternative... not a dead-end," so the portfolio content gets the primary (left, wider) position, with the agent zone as a persistent, always-visible dock rather than a lesser afterthought or a takeover of the main content position. This also happens to be forced by the DOM-order constraint below, but it was the preferred call independent of that.
  - **Why `grid-template-areas` and not DOM order for the split:** the *mobile* stacking order (intro → agent teaser → browse-manually → sections) had to stay exactly as Phase 1 left it — "nie psuj tego, co działa." Grid areas decouple visual desktop position from source order entirely, so the agent zone's markup can come *before* the content zone's in the DOM (preserving the mobile order and screen-reader/tab order on both breakpoints) while still rendering on the *right* at desktop. Content left / agent right was reachable without reordering anything for mobile's sake.
  - **Why 380px fixed, not a fraction:** wide enough for a comfortable future chat transcript + input (Phase 2) without a min/max-width dance; simple, matches "the simplest thing that actually works." At the 1024px floor this leaves ~644px for the content column before its own padding, still a comfortable reading width, so no extra clamping was needed for the boundary case.
  - **Why the intro (photo/name/blurb) got pulled out of both zones into its own compact grid row** (`components/layout/Intro.tsx`, split out of the old `Hero.tsx`) rather than living inside the agent zone: the agent zone's whole job is holding a chat transcript that Phase 2 will grow into that space unmodified (docs/ROADMAP.md); permanently anchoring unrelated branding content there would mean gutting it again later. Putting intro content inside the *content* zone instead would have meant the content-zone wrapper (intro + sections + footer) had to come before the agent-zone wrapper in DOM order for correct grid nesting — which would have broken the mobile stacking order this whole design was trying to preserve. A third, minimal top row was the option that kept both constraints satisfiable at once. Desktop's intro row is a compact inline strip (small photo, small type) specifically so it doesn't eat meaningfully into the fixed-height budget the two scrolling zones need.
  - **Reveal-in-view without moving the agent zone or the page:** `PortfolioSections` now keeps a ref per section and calls `scrollIntoView({ block: "nearest" })` when `activeSectionId` changes (verified live: only `.layout-content`'s `scrollTop` moves, `.layout-agent` and the page both stay at `0`). `block: "nearest"` was chosen over `"start"` specifically to keep the scroll distance — and therefore the time before the reveal is actually on screen — as short as possible, matching the "reveal lands with the spoken answer" latency budget. `prefers-reduced-motion` is checked explicitly (`behavior: "auto"` when set) rather than relying on browser-default handling of smooth `scrollIntoView`, which isn't consistent enough across browsers to trust.
  - **1024px, matching Tailwind's existing `lg:` breakpoint** used elsewhere in these same components (the mobile-only "Browse manually" button) — one shared breakpoint value, verified live that `.app-layout`'s `display`/`overflow` flips at exactly the same width `lg:hidden` does, so nothing can desync at the edge.

## 2026-08-30 — Phase 1 (frontend shell) built

- 2026-08-30 — **`amplify.yml` simplified: dropped `appRoot: frontend` + `cd .. && npm ci`, build now runs straight from the repo root** — the `appRoot`/`cd ..` construction failed on a real Amplify build: `preBuild` succeeded, but the `build` phase started from a different working directory and walked above the repo root, hitting `ENOENT` on `package.json`. Fixed spec: `npm ci` and `npm run build --workspace=frontend` from root, `artifacts.baseDirectory: frontend/dist`. `main`'s first Amplify job is `FAILED` for this exact reason; the fix commit's job is `SUCCEED`, and `dev`'s first build (created after the fix) was `SUCCEED` from the start.
- 2026-08-30 — **Palette: near-monochrome dark neutral (Tailwind's built-in `neutral` scale) + exactly one warm amber accent (`#e8a33d`)** — deliberately not the blue/purple gradient most AI-product templates default to; the accent is reserved for the agent entry point, active-section state, and links, so it stays meaningful rather than decorative.
- 2026-08-30 — **Type scale: Fraunces (serif, Google Fonts) for headings only, system-ui stack for everything else**, plus a named Tailwind `fontSize` scale (`display`/`h1`/`h2`/`h3`/`body`/`small`) instead of Tailwind's default sizes — one distinctive visual signature without paying webfont cost across all body text, and a scale every component reaches for instead of ad hoc values.
- 2026-08-30 — **Reveal animation: CSS `grid-template-rows` 0fr→1fr + opacity transition, no animation library** — matches the "lightweight animation approach" already called for in `docs/ARCHITECTURE.md` § Frontend; no JS height measurement, no layout thrash, and it collapses to an instant snap under `prefers-reduced-motion` (handled once, globally, in `styles/index.css`).
- 2026-08-30 — **`reveal_section`'s state lives in a plain module-level store (`frontend/src/content/activeSectionStore.ts`), not React Context** — `revealSection(sectionId)` has to be callable from Phase 3's `uiActions.ts` tool-call handler, which is ordinary code outside the component tree and has no component to read Context from; a vanilla subscribe/notify store (read via `useSyncExternalStore`) works identically from a click handler or a tool-call handler. `revealSection()` always opens a section; the click-only `toggleSection()` wraps it with close-on-second-click, since the agent should never accidentally collapse the section it's talking about.

## 2026-08-29 — Architecture review follow-ups

- 2026-08-29 — **Reasoning path resolved: Lambda Function URL with response streaming** (see [ARCHITECTURE.md § Real-time media transport](ARCHITECTURE.md#real-time-media-transport)) — API Gateway REST buffers full responses and HTTP API doesn't support response streaming either, so Function URL is the only option that satisfies Phase 2's streaming requirement, not merely the preferred one. Consequence: throttling now lives entirely in the function (token bucket, no API Gateway usage-plans available); CORS is set on the Function URL directly; CloudFront stays deferred.
- 2026-08-29 — **New open question (OQ-1, highest priority): tool-use sequencing vs. streaming, and the Lambda→browser wire format** — a `tool_use` block ends the assistant's turn, so a full answer after a tool result needs a second model call, risking dead air between `reveal_section` firing and the spoken answer arriving. Adopted approach: `reveal_section` stays a real tool (two model calls per turn accepted); verify in Phase 2 whether Haiku 4.5 can emit `get_content` + `reveal_section` in parallel in one turn; plan B is a structural marker in the text stream instead of a real tool. Wire format proposed as NDJSON (`{type: text|action|done}`), to be settled before `handler.ts` is written.
- 2026-08-29 — **Corrected: the per-session message cap is not an abuse control** — `sessionId` is client-generated and trivially rotated, so the cap only bounds accidental overuse (a stuck retry loop), not deliberate abuse. The daily circuit-breaker is the only real cost backstop. Removed the earlier claim that the client-side cap gates STT/TTS abuse, and reconciled the "enforced server-side" wording with this limitation.
- 2026-08-29 — **OQ-8 (Cognito guest-role abuse ceiling) reclassified as blocking** — must be resolved *before* the Identity Pool is provisioned to production, not just "during Phase 4". Guest credentials are pullable by any script without loading the page, there is currently no server-side quota on the Transcribe/Polly path, and Polly generative runs ~$30/1M characters — enough to breach the ceiling in an afternoon of deliberate abuse.
- 2026-08-29 — **"Not templated / design-forward" visual bar formally moved from Phase 1's exit criteria to Phase 9** — resolves a conflict with the README's "does not need to be fully polished" framing for the Tuesday demo. Phase 1 keeps a timeboxed design pass only; the full bar is Phase 9's to clear.

## 2026-08-29 — Initial architecture

- 2026-08-29 — **Project documentation lives under `docs/`**; root keeps only `README.md` as the entry point — keeps the root free for code/config once scaffolding starts, and gives one place for architecture, roadmap, decisions, specs, and runbooks.
- 2026-08-29 — **Product = single-page portfolio with 3 entry points** (CV download, manual click-through, AI agent) driving the same content/UI — the agent is an alternate navigation of the portfolio, not a bolted-on feature.
- 2026-08-29 — **Hard cost ceiling: ~100 PLN/month (~$25) worst case**, architecture must scale toward zero when idle — it's a personal portfolio that sits unvisited for weeks.
- 2026-08-29 — **Banned OpenSearch Serverless (classic) as a vector store** — ~4 OCU minimum ≈ ~$700/mo with zero traffic, AWS defaults you into it from the Knowledge Base wizard, and deleting the KB doesn't delete the collection.
- 2026-08-29 — **No always-on compute** — Lambda + API Gateway / Function URLs only; no provisioned capacity, no persistent servers.
- 2026-08-29 — **AWS Budget alarm is Phase 0**, not an afterthought — configured before any feature work.
- 2026-08-29 — **Chose AWS Amplify over Vercel/GitHub Pages** — the narrative value of a second real Bedrock/AWS proof point outweighs the low, already-assessed config risk; funds already exist in the org account.
- 2026-08-29 — **Branch-based deploys: `dev` → staging, `main` → production** — also gives dev/prod separation from day one (a FlowJob/Rhymind lesson).
- 2026-08-29 — **Region: `eu-central-1` (Frankfurt)** — lowest latency from Poland for a voice app; supports Polly generative, Transcribe streaming, Bedrock (verify model specifics in Phase 0).
- 2026-08-29 — **Frontend: Vite + React + TypeScript static SPA, Tailwind** — React was the brief default; Vite over Next.js because there's no SSR need and the "no route changes" rule means no router.
- 2026-08-29 — **Chose Claude Haiku 4.5 on Bedrock over higher tiers** — voice latency and cost; answering CV questions with supplied context doesn't need frontier reasoning. Sonnet is the fallback if quality falls short; Opus/Fable are ruled out (~10× cost, slower, unjustified).
- 2026-08-29 — **Bedrock requests stream** — first tokens drive first audio and the section reveal; perceived latency is what matters.
- 2026-08-29 — **Chose Polly generative over ElevenLabs** — Polly generative quality judged acceptable after a listening test; ElevenLabs is 3–6× costlier with subscription-tier pricing that breaks the ceiling in idle months, and adds a non-AWS vendor/key.
- 2026-08-29 — **TTS = Polly generative engine tier specifically** (not standard/neural) — meaningfully more natural, and supports streaming so audio can start before generation finishes (exact streaming API to be verified).
- 2026-08-29 — **STT = Amazon Transcribe streaming**; **rejected the Web Speech API** — too limited/inconsistent, and the portfolio should showcase advanced, not basic browser features.
- 2026-08-29 — **Chose hybrid tool-fetch (Option C) over vector retrieval** — the corpus is a small, known, enumerable topic set with business/technical layers; the agent needs to *choose*, not *search*. ~5× cheaper and lower-latency than full-context.
- 2026-08-29 — **Considered and parked full-context + prompt caching (Option A)** — TTFT scales with corpus size and Bedrock's ~5-min cache TTL means a paused visitor pays full price on the next turn.
- 2026-08-29 — **S3 Vectors is the sanctioned migration path** if the corpus outgrows enumeration — additive behind the existing `get_content` tool, no provisioned compute, ~cents/month at this scale.
- 2026-08-29 — **Rejected non-AWS vector DBs** — no meaningful saving at this scale, Pinecone's ~$50/mo minimum alone breaches the ceiling, and each adds a vendor + API key + cross-cloud hop.
- 2026-08-29 — **Agentic UI = structured action alongside the answer** (`reveal_section`), executed by the frontend against the same components a manual click drives — single page, no new tabs, no route changes, reveal and answer simultaneous.
- 2026-08-29 — **Real-time media plan: browser talks directly to Polly/Transcribe** via a tightly-scoped Cognito Identity Pool guest role; the Lambda owns reasoning + session cap + circuit-breaker + logging; Bedrock is never called client-side. (Plan B: API Gateway WebSocket proxy. To be validated — OQ-3.)
- 2026-08-29 — **Data stores: DynamoDB on-demand** for session caps, the daily spend counter, and conversation logs; S3 for the content corpus (dev/prod prefixes). Chosen for "scales to zero", not cost.
- 2026-08-29 — **Real-time circuit-breaker is a self-managed DynamoDB counter**, not AWS Budgets — Budgets/Cost Explorer data lags hours and can't stop a spike in progress. Over threshold → degrade to text-only or disable the agent.
- 2026-08-29 — **WAF deferred for MVP** — the ~$5/mo web-ACL floor conflicts with "scale toward zero"; rely on throttling + session cap + breaker, add WAF only if abuse appears.
- 2026-08-29 — **Logging: conversation content + timestamps only, zero identifiers** — random non-identifying `sessionId`; purpose is topic insight for the owner, not visitor tracking. Admin dashboard deferred.
- 2026-08-29 — **Bilingual EN/PL via an explicit UI language toggle** — one choice drives Transcribe language, Polly voice, and the response-language instruction; corpus stays English-only and is translated at generation time, never duplicated.
- 2026-08-29 — **Accept distinct Polly voice identities per language** — no single generative polyglot voice cleanly covers EN+PL; pair an EN generative female voice with PL `Ola`/`Ewa`. Revisit if a suitable polyglot voice ships.
- 2026-08-29 — **Infra-as-code = AWS CDK (TypeScript)** for Lambda / DynamoDB / API / Cognito / IAM / Budgets; the Amplify Hosting app is connected via console to keep the frontend build path simple. Backend deploys stay manual so infra changes are deliberate.
- 2026-08-29 — **Guardrails: out-of-scope = explicitly name the scope boundary; sensitive = soft redirect to "ask him directly"; injection = hold persona/scope, never leak the system prompt.** Injection handling is treated as part of the demo and gets a dedicated test phase.
- 2026-08-29 — **`content/` corpus is treated as data, not instructions** — the system prompt says so explicitly, so a poisoned content file can't redirect the agent.
- 2026-08-29 — **Build order: MVP first with seed/placeholder content, full content authoring as an explicit post-MVP phase** — lets the pipeline be tested end to end immediately; content is still on the critical path for Tuesday.
- 2026-08-29 — **Deferred (not decided now):** landing "about me" copy, the conversation opener script/example questions, whether portfolio-as-a-project is proactively surfaced, the admin dashboard, the custom domain, fine-grained Amplify build specifics.
